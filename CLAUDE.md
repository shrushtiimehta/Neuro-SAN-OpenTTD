# Neuro-SAN-OpenTTD

A **neuro-san-studio fork** that plays the **nttd** benchmark (long-horizon planning on OpenTTD)
with a multi-agent system that *learns across sessions*.

`README.md` explains the design. This file is the orientation and the traps — read it before
changing anything.

---

## 1. Three repos, one tree

| path | what it is | edit it? |
|---|---|---|
| `.` | this fork. Our networks, the knowledge layer, the runner. | **yes** |
| `nttd/` | the **engine**. Wraps an OpenTTD 15.3 server, exposes it as JSON on `:8000`, scores runs. | no — cloned |
| `nttd-workbench/` | the **game layer** — gateway, plan, clock, siting/fleet tools. Our player registries reference its Python **in place**. | no — cloned |

Both clones are gitignored. Everything upstream-studio is tracked, so `git checkout <path>`
restores anything.

---

## 2. Two layers, and the split is load-bearing

**Knowledge layer** — `coded_tools/`. Reads and writes files and telemetry. **Holds no session
credentials and takes no game action**, so it cannot spend a game day while thinking about one.

**Game layer** — `nttd-workbench/agents/neuro_san/coded_tools/`. Talks to the engine over HTTP.
**Not duplicated here.** Referenced as `agents.neuro_san.coded_tools.*`.

A tool that did both would make "did the agent play badly or record badly" unanswerable.

## 3. Five networks

```text
registries/
  manifest.hocon          AGENT_MANIFEST_FILE points here — and it is also the studio's own
                          default, so the unset-manifest trap is gone
  nttd_common.hocon       caps, models, sly_data allow-list, the shared prompt fragments
  nttd_air_player.hocon   GENERATED — do not hand-edit
  nttd_rail_player.hocon  GENERATED — do not hand-edit
  nttd_opener.hocon       opens a session: plan + claims to test
  nttd_closer.hocon       closes it: verdicts, promotions, advance
  nttd_watcher.hocon      mid-session: on_track / underperforming / doomed
```

The players are generated by `scripts/nttd/sync_player_registries.py` from the workbench
registries. It rewrites class paths (the workbench sets `AGENT_TOOL_PATH_ONLY=true` and names
tools flat; we don't, so ours resolve fully-qualified — one server cannot do both), wires each
agent to its own playbook reader, and adds the knowledge tools. **Re-run it after pulling
nttd-workbench.** Never edit the generated files: change the workbench network instead.

**The prompt fragments in `nttd_common.hocon` are ours** — `nttd_ground_rules`,
`nttd_worker_conduct`, `nttd_curator_conduct`. Change agent behaviour there, not in a generated
file, and it survives the next sync.

## 4. Baseline, earned, working

Three things, kept apart so each property is structural rather than enforced by parsing:

| | where | written by |
|---|---|---|
| **baseline** | `coded_tools/config_files/seed_playbook_*.md` | a person. **No tool writes here.** |
| **earned** | `state/learned/<mode>/playbook_*.md` | `promote_claim`. Append-only, revocable. |
| **working** | `state/<mode>/playbook_*.md` | composed on `prepare()`: filtered baseline + earned |

So the baseline cannot be damaged by the loop, only earned lines are demotable, and a rule learned
playing air cannot reach rail — it is not in rail's directory.

**Air and rail are separate** because `promote_claim` takes a `domain` and no mode: a claim is
condition-gated by Gate 3, a promoted playbook line is just text and nothing would flag it. The
seeds stay ONE set, filtered on copy by the `### Air:` / `### Rail:` headings they already use.

**The `### Learned rules` heading in each seed is load-bearing.** It is the splice point
`prepare()` and `promote_claim` both write under. A seed without it silently produces a playbook
that can never carry anything learned.

**The commons** (`state/claims.md`) is one **append-only** ledger. A status change appends a *new
revision*; current standing is computed by folding the file. Nothing is overwritten because
nothing is overwritable.

**Four gates, enforced in `coded_tools/claims.py`, not in prompts.** See `README.md`. There is no
`replace_line` on playbooks, deliberately.

## 5. logs/ versus state/

**The test is whether the next session needs it.**

- `logs/nttd/` — transient. Server stdout, engine stdout. `rm -rf logs/` is always safe.
- `state/` — maintained. Playbooks, claims, plan, and `state/telemetry/` (per-turn rows, the
  finished-session rows the champion is computed from, per-turn agent state).

Tracked in git: `state/claims.md`, `state/learned/`, `state/telemetry/`. Everything else in
`state/` is derived and ignored.

The engine keeps its own richer record in `nttd/logs/sessions/<id>/`: `result.parquet` (the scored
claim), `spend.parquet` (cost by model and role), `snapshots.parquet` (one row per game day),
`tiles.parquet` (the whole map), `actions.parquet`. **Do not rebuild any of that** — an earlier
attempt at per-turn situation snapshots duplicated `snapshots.parquet` at lower resolution and was
removed.

## 6. Running it

```bash
source venv/bin/activate && ./apps/run_all.sh --tier t1 --mode air --fresh
```

Order matters: engine → agent server → world → play. The script starts the **agent server before
the world**, because a paused session costs nothing to leave waiting but a server that fails to
load after the world exists has burned a session id.

Validate wiring without starting anything — parses every registry, imports every tool class, and
checks no tool is unreachable:

```bash
PYTHONPATH=.:nttd-workbench python3 scripts/nttd/check_wiring.py
```

Ports are **8085** (agents) and **4175** (nsflow), not the studio's usual 8080/4173, which are
commonly already held. Engine on 8000.

## 7. Traps

**`PYTHONPATH=.:nttd-workbench` is required and `ns run` does not read it from `.env`.** Without
the second path the two players silently fail to load. `run_all.sh` exports it.

**A tool declared but named by no agent's `tools` list invalidates the WHOLE registry** and
neuro-san skips it silently. It presents as "only the boundary agents loaded", which looks exactly
like the PYTHONPATH trap and is not. `check_wiring.py` checks reachability now — it did not, and
that cost a debugging session.

**Stepped only.** In realtime the clock runs whatever the agent does, which makes a slow turn a
lost game month and every measured figure incomparable. The runner refuses.

**The runner owns the turn stamp.** `advance_days` reads `sly_data["turn_stamp"]` to bound the
per-turn day budget. Without it a turn grows until the server cancels it.

**The `sly_data` allow-list is explicit.** neuro-san's redactor is security-by-default: with
nothing listed, cross-turn memory dies at the turn boundary — the defect that made an earlier
network resubmit one refused purchase 35 times. Credentials never go on it. The runner copies
`sites`, `decisions`, `routes`, `plan`, `refusals` out of the returned sly_data **by name**,
because the session id and token live there too.

**Client stream timeout > server `max_execution_seconds`** — 7200 vs 6000.

**`cargo_delivered_total` is in the COMPANY row, not in `situation.earning`.** Reading it off
`earning` returned 0 on every turn of every run: the board's tiebreak metric dead, `diagnose`
reporting "built but delivering nothing" on a healthy run, and the opener raising claims against a
premise that was never true. The runner makes a second call to `/state/company/{id}`.

**Paths derived by counting levels from a file's own location break silently on a move.** This bit
three times in one day — `run_all.sh`'s studio root, the tests' `REPO_ROOT`, and `check_wiring`'s
`paths.py` lookup. They do not fail; they point somewhere else that looks plausible. `run_all.sh`
now asserts the root it computed actually contains `registries/manifest.hocon`.

**pylint's `useless-suppression` is enabled.** A `# pylint: disable=` on a line ruff later reflows
becomes its own error. The deferred `neuro_san` imports in `apps/runner.py` sit under multi-line
`def` signatures because that is the only form surviving both tools.

**Python 3.14** in all three venvs. Nominally fine but the langchain/neuro-san stack is barely
road-tested on it. First suspect for odd import errors.

## 8. State of play

**Tested:** 84 tests, `make test` green (ruff, pylint 10.00, pymarkdown, pytest). Covers all four
gates, the plan-confidence cap, the append-only ledger and playbooks, the per-mode split, the
boundary agents' capabilities, and that no prompt names a status the schema dropped.

**Has run:** real sessions against a live engine, end to end. Only a handful. Treat measured
figures as provisional.

**Untested:** `apps/runner.py` — the turn loop — needs a live engine, so no unit test reaches it.
It is the largest untested piece.

**Outstanding:**

1. **More sessions.** The loop has produced claims but nothing has been promoted, demoted, or
   re-tested under Gate 3 with matching conditions yet.
2. **`actions.parquet` has an empty `agent_id` column.** The workbench does not populate it, so an
   action cannot be attributed to Scout vs Builder vs FleetGrowth. Fix belongs at the workbench
   gateway.

## 9. Source of truth for strategy

Every line in the six seed playbooks came from `nttd-workbench/agents/strategy/{common,air,rail}.md`,
`nttd/docs/gameplay_guide.md`, `nttd-workbench/agents/neuro_san/DESIGN.md`, or the workbench
registries. Nothing was invented. The per-line citation tags were removed — the agents cannot open
those files, so a citation cost tokens and pointed at nothing. **Keep the property, not the tags:**
a new seed line should be traceable to one of those documents, or marked as a claim to be tested.
